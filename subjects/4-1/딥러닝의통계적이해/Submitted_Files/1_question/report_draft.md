## 1. 프로젝트 개요

본 과제에서는 Google의 Teachable Machine(https://teachablemachine.withgoogle.com)을 이용하여 수학 시험 문항 이미지를 자동으로 분류하는 머신러닝 모델을 제작하였다. 분류 대상은 수학 문항의 **응답 방식**과 **지문 구성**에 따라 다음 4가지 유형으로 정의하였다.

| 클래스 번호 | 유형명 | 설명 |
|-----------|-------|------|
| Class 1 | **객관식_그림없음** | 그림 없이 텍스트만으로 구성된 지문에 선택지(①~⑤)가 주어지는 형태 |
| Class 2 | **객관식_그림있음** | 그래프·도형·표 등 시각 자료가 포함된 지문에 선택지(①~⑤)가 주어지는 형태 |
| Class 3 | **주관식_그림없음** | 그림 없이 텍스트만으로 구성된 지문에 빈칸 또는 서술형으로 답하는 형태 |
| Class 4 | **주관식_그림있음** | 그래프·도형·표 등 시각 자료가 포함된 지문에 빈칸 또는 서술형으로 답하는 형태 |

### 1.1 분류 기준 선정 이유

초기에는 단독문항/셋트문항을 기준으로 4분류를 설계하였으나, 실제 기출 자료를 검토한 결과 셋트형 문항보다 **그림 삽입 문항의 사례가 훨씬 많아** 데이터 확보가 용이하다는 점에서 그림삽입 여부로 기준을 변경하였다.

이 분류 체계는 두 가지 기준을 교차한 2×2 구조로, 각 클래스는 다음과 같은 명확한 시각적 특징을 가진다:
- **객관식 판별 기준**: 선택지 번호(①②③④⑤)의 존재 유무 → 시각적으로 명확
- **그림삽입 판별 기준**: 그래프·도형·수식 다이어그램 등 비(非)텍스트 시각 요소의 존재 유무

## 3. 모델 학습

### 3.1 학습 환경

Teachable Machine은 브라우저 내에서 TensorFlow.js를 사용하여 학습을 수행하며, ImageNet으로 사전학습된 **MobileNet** 모델의 특징 추출층을 고정하고 마지막 분류층만 새로운 데이터로 재학습하는 **전이학습(Transfer Learning)** 방식을 채택한다. 입력 이미지는 224×224 픽셀 컬러 이미지로 처리된다.

### 3.2 하이퍼파라미터 설정

Teachable Machine의 고급 설정(Advanced)에서 다음 파라미터를 조정하였다.

| 파라미터 | 설정값 | 설명 |
|---------|--------|-----|
| Epochs | **100** | 클래스당 10장의 소규모 데이터에서 충분한 수렴을 위해 100회로 설정 |
| Batch Size | 16 | 미니배치 크기 |
| Learning Rate | 0.001 | MobileNet 전이학습의 표준 학습률 |

![학습 파라미터 고급 설정 화면](2_edit_option.png)

*[그림 2] 에포크 100, 배치 크기 16, 학습률 0.001로 설정된 고급 학습 옵션 화면*

### 3.3 학습 과정 설명

"모델 학습시키기" 버튼을 클릭하면 브라우저 내에서 학습이 시작되며, 에포크(Epoch)가 실시간으로 증가하면서 손실(Loss) 값이 감소하는 과정을 확인할 수 있다. 학습 중 탭을 전환하면 학습이 중단되므로 완료까지 동일 탭을 유지해야 한다. 약 2~3분 소요 후 학습이 완료된다.

각 에포크에서 모델은 미니배치 단위로 순전파(Forward Propagation) → 손실 계산 → 역전파(Backpropagation) → 가중치 업데이트를 반복하며, 이 과정을 100회 수행하여 분류 성능을 점진적으로 향상시킨다.

### 4.3 결과 해석

**잘 분류된 경우**

주관식_그림없음, 주관식_그림있음, 그리고 객관식_그림있음(사례 A, C)은 높은 신뢰도로 정확하게 분류되었다. 특히 객관식_그림있음 사례 C(97%)는 포물선 그래프와 수치 표가 이미지 내에 뚜렷하게 존재하여 MobileNet의 특징 추출기가 비(非)텍스트 시각 요소를 효과적으로 포착한 것으로 판단된다.

**오분류 발생 사례 분석**

전체 6회 테스트 중 객관식 계열에서만 오분류가 2회 발생하였고, 주관식 계열은 2회 모두 정확히 분류되었다. 오분류가 발생한 두 이미지의 공통점을 관찰한 결과, **선택지 원문자(①~⑤)가 그림(그래프·도형) 바로 옆이나 아래에 연속적으로 배치**된 레이아웃이었다. 이로부터 다음과 같은 원인을 추론할 수 있다.

1. **원문자-그림 연속 배치로 인한 시각적 혼동**: 선택지 원문자(①~⑤)가 그림과 인접하여 배치된 경우, 모델은 원문자를 독립적인 선택지 패턴으로 인식하지 못하고 그림의 일부 구성 요소로 처리할 가능성이 높다. 이 경우 선택지라는 핵심 판별 특징이 모델에 전달되지 않아 객관식과 주관식의 경계가 무너진다.

2. **소규모 학습 데이터의 한계**: 클래스당 10장의 학습 데이터에 원문자-그림 연속 배치 유형이 충분히 포함되지 않았다면, 모델은 이 패턴을 학습하지 못한 채 더 익숙한 클래스로 예측하게 된다. 원문자-그림 연속 배치 사례를 추가 수집하여 재학습하면 이 오분류 문제가 크게 개선될 것으로 추측된다.

3. **편향-분산 트레이드오프**: 데이터가 적을수록 모델은 학습 데이터에 과적합(overfitting)되어 미학습 레이아웃 패턴에 대한 예측 분산(variance)이 커진다. 클래스당 50장 이상, 특히 원문자-그림 연속 배치를 포함한 다양한 레이아웃 변형을 균형 있게 확보하는 것이 근본적인 해결책이다.

## 5. 통계학적 고찰

### 5.1 전이학습의 통계학적 의미

Teachable Machine은 ImageNet으로 사전학습된 MobileNet의 특징 추출층을 고정하고, 마지막 분류층만 새로운 데이터로 재학습하는 방식이다. 이는 통계학에서 **베이즈 추정(Bayesian Estimation)** 의 관점과 유사하다. 대규모 이미지 데이터로 학습된 특징 표현이 **사전 분포(Prior Distribution)** 의 역할을 하며, 소규모의 새로운 데이터(40장)가 **우도(Likelihood)** 를 제공하여 사후 분포를 업데이트하는 구조로 해석할 수 있다. 이 덕분에 적은 데이터로도 효과적인 분류가 가능하다.

### 5.2 출력값의 확률적 해석

모델의 출력값(Confidence)은 소프트맥스(Softmax) 함수를 통해 계산된 **클래스별 조건부 확률** $P(y=k \mid x)$ 이다.

$$P(y=k \mid x) = \frac{e^{z_k}}{\sum_{j=1}^{4} e^{z_j}}, \quad k \in \{1, 2, 3, 4\}$$

4개 클래스의 신뢰도 합은 항상 1이 되며, 가장 높은 확률을 가진 클래스가 최종 예측값으로 선택된다. 오분류 사례 B에서 객관식_그림없음 48% / 주관식_그림있음 33% / 객관식_그림있음 16% / 주관식_그림없음 1%로 신뢰도가 분산된 것은, 모델이 해당 이미지의 특징을 어느 클래스에도 확신 있게 귀속시키지 못했음을 의미한다.

### 5.3 데이터 양과 모델 성능의 관계

클래스당 10장의 소규모 데이터를 사용하였으므로 **과적합(Overfitting)** 가능성이 존재한다. 통계학적으로 표본 크기(sample size)가 증가할수록 추정의 분산(variance)이 감소하고 일반화 성능이 향상되는 것과 동일한 원리이다. 실제 현장 적용 수준의 정확도를 달성하려면 클래스당 최소 50~100장 이상, 다양한 연도·시험 유형의 이미지가 필요하다.

## 6. 결론

본 과제에서는 Teachable Machine을 이용하여 수학 문항 이미지를 4개 유형(객관식/주관식 × 그림없음/그림있음)으로 분류하는 머신러닝 모델을 제작하였다. 테스트 결과, 주관식 계열은 2회 모두 높은 신뢰도로 정확히 분류된 반면, 객관식 계열은 3회 중 2회 정확히 분류되었다.

오분류 사례를 분석한 결과, 공통적인 원인은 **선택지 원문자(①~⑤)가 그림과 연속으로 배치된 레이아웃**이었다. 이 경우 모델이 선택지 패턴을 독립적으로 인식하지 못하고 그림의 일부로 처리하여 오분류가 발생한 것으로 추측된다. 이는 단순히 데이터 수량 부족의 문제이기도 하지만, 보다 근본적으로는 **원문자-그림 연속 배치 유형을 포함한 다양한 레이아웃 변형 데이터가 학습에 포함되지 않은 것**이 핵심 원인이다.

향후 원문자-그림 연속 배치 사례를 충분히 수집하여 재학습한다면 이 오분류 문제가 크게 개선될 것으로 기대된다. 나아가 클래스당 데이터를 50장 이상으로 확장하고 다양한 연도의 기출 문항을 포함한다면 실용적인 수준의 수학 문항 자동 분류 시스템으로 발전시킬 수 있을 것이다.
