@subjects/4-1/<과목폴더명>/  
폴더 하위의 강의노트(.md)를 각각 심층 검토해서 수정·보완·아이디어를 제시해줘.
인터넷 심층 리서치로 근거를 기반으로 조치해줘.

## 진행 방식 (반드시 이 순서로)
1. **검토 먼저, 수정 나중**: 1차로 강의별 "오류 / 핵심 보완 / 심층 확장"을 정리한
   검토 리포트를 제시하고, 내가 승인하면 2차로 원본 파일을 수정한다.
   - 1차 수정 범위: **오류 수정 + 핵심 보완**
   - 2차: 리서치 기반 **심층 확장**

## 검토 방법
- 강의 수가 많으면 3~5개씩 묶어 **병렬 검토 에이전트**로 돌린다.
  각 에이전트는 담당 파일을 전부 Read하고, 의심스러운 핵심 주장은
  **반드시 WebSearch/WebFetch로 검증**(위키피디아·공식문서·교과서·논문 우선)한 뒤
  근거 URL과 함께 구조화된 findings를 반환한다.
- 각 강의별로 다음을 점검:
  1. **사실/개념 오류, 수식(LaTeX) 오류, 표기·용어(한영) 오류, 개념 혼동**
  2. **정답·해설의 정확성** (객관식·O/X·서술형 정답이 실제로 맞는지)
  3. **코드 정확성** — 코드를 실제로 돌렸을 때 "실행 결과" 주석이
     코드와 일치하는지 직접 재계산해 검증 (불일치가 자주 숨어 있음)
  4. **누락된 핵심 내용** (시험·이해에 필수인데 빠진 개념/공식/예시)
  5. **리서치 기반 심층 확장** (최신 동향·실무 사례·비교표·코드 개선)
- 과장 금지: 실제 오류만 보고하되, 보완·확장은 충실히. 근거 URL을 최대한 첨부.

## 리포트 형식
- 🔴 명백한 오류(수정 필수) → 표로: [강|위치|문제|올바른 내용|근거URL]
- 🟠 정밀화 권장(경미하나 오해 소지)
- 🟡 핵심 보완(누락된 필수 내용) — 강별
- 🟢 심층 확장 아이디어 — 강별

## 수정 시 규칙 (승인 후)
- 파일별로 **Edit 도구로 부분 수정만** 한다. Write로 전체 덮어쓰기 금지.
- **기존 내용을 삭제·축약하지 않는다.** "중략/이하 생략/기존 구조를 따름" 같은
  placeholder를 절대 넣지 않는다. 수정 후 줄 수가 줄면 안 된다(보완으로 늘어야 정상).
- 기존 마크다운 구조·이모지 섹션 스타일·LaTeX 표기를 그대로 유지하고,
  맞는 내용은 건드리지 말고 지정 항목만 수정/추가한다.
- 정답이 바뀌는 수정은 신중히 — KNOU 교재/기출 표기와 충돌 시 주석으로 병기.

## 마무리 검증
- grep로 핵심 수정이 반영됐는지, placeholder가 없는지 확인.
- git diff --numstat 로 강의별 변경량을 요약 보고.
- Submitted_Files 등 과제 제출물 폴더는 **건드리지 않는다**.
- 커밋·푸시는 내가 요청할 때만 한다.
