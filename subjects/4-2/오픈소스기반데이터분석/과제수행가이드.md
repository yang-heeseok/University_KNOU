## ① 문 1-1 — 인증키 발급 (3점)

1. data.go.kr 로그인 → [해당 API 페이지](https://www.data.go.kr/data/15156057/openapi.do) → **활용신청**.
2. 활용목적에 "학교 과제(데이터 분석 실습)" 정도를 적고 신청. 개발계정은 **자동승인**이다.
3. **마이페이지 → 인증키 발급현황**에서 64자리 영숫자 인증키를 확인한다. 이 API의 처리상태가 "승인"인지도 **활용신청 현황**에서 확인한다.
4. **활용신청 현황**에서 이 API를 클릭해 개발계정 상세 화면을 연다. 이 화면 한 장에 서비스명, 처리상태 "승인", 활용기간, End Point, 일반 인증키가 모두 있으니 이것을 캡처한다. 그림판 등으로 **키의 가운데 대부분을 검은 박스나 `●●●●`로 가린다**. 앞 8자와 뒤 4자 정도만 남긴다. 흰 공백으로 지우면 가린 것인지 알아보기 어렵다. 이메일과 이름 등 개인정보도 가린다.

> 승인 직후에는 키가 동기화되지 않아 1~2시간 동안 오류 `30`(등록되지 않은 서비스키)이 날 수 있다. 신청은 미리 해 둔다.

## ② 문 1-2 — 데이터 수집 (7점)

### 2-1. 인증키 설정 (코드에 키를 쓰지 않는다)

인증키 발급현황의 64자리 키를 그대로 쓴다. 영문 소문자와 숫자로만 이루어져 있어서 Encoding/Decoding 구분이 없다. (2026-10-12 실호출로 확인)

PowerShell (VS Code 터미널) 기준, 터미널을 열 때마다 1회 실행:

```powershell
$env:DATA_GO_KR_KEY = "여기에_64자리_인증키"
```

### 2-2. 실행

```powershell
pip install requests pandas matplotlib
cd "subjects/4-2/오픈소스기반데이터분석/code"
python q1_collect.py
```

동작:

- 2015~2024년 × 품종 `01/02/03/06` = **40회 조합**을 호출한다.
- 조합별 `totalCount`가 200을 넘으면 **다음 페이지까지 이어서** 받는다.
- 결과는 `code/data/raw_cabbage.json`에 저장된다.

### 2-3. 성공 판정 — 캡처 전에 반드시 확인

| 확인 항목 | 정상 |
| --- | --- |
| 첫 줄 (2015년 01 봄배추) | `totalCount= 66 수집= 66 ... OK` |
| 요약의 `totalCount 불일치 조합` | `0개` |
| 각 줄 앞 `[resultCode resultMsg]` | `[0 정상]` (2026-10-12 실호출로 확인) |
| `0건 조합` | 비어 있거나, 해당 연도에 그 품종 거래가 실제로 없던 경우뿐 |

**캡처 범위**: 터미널 로그 전체 (40줄 + 요약). 한 화면에 안 들어가면 두 장으로 나눈다. **66건 줄과 요약 블록은 반드시 보여야 한다.**

### 2-4. 오류 대처

| 증상 | 원인 → 조치 |
| --- | --- |
| `인증/호출 오류 30: SERVICE_KEY_IS_NOT_REGISTERED_ERROR` | 키 복사 오류(공백 포함 등)이거나 승인 직후 미동기화 → 키 재확인, 1~2시간 대기 |
| `인증/호출 오류 20: SERVICE_KEY_IS_NULL` | 환경변수 미설정 → 같은 터미널에서 `$env:...` 다시 실행 |
| `22` / `23` | 일일 / 초당 호출량 초과 → 다음 날 재실행 / 대기 시간 늘리기 |
| 첫 줄이 66이 아님 (특히 0) | 코드 값 오타 → `BASE_COND`의 `0110211`, `04` 등이 **문자열**인지 확인 |
| `KeyError: 'response'` 등 | 응답 구조가 예상과 다름 → `print(res.json())`으로 실제 구조를 보고 `extract_items`를 맞춘다 |

> 2026-10-12 실호출로 확인한 정상 응답: `response.header.resultCode = "0"`, `response.body.totalCount = 66`, 목록 경로 `response.body.items.item`. 가격(`exmn_dd_prc`)은 `"9000"` 같은 문자열이고, 단위는 `unit = "kg(그물망 3포기)"`, `unit_sz = "10"`이다. 이 밖에 `exmn_dd_cnvs_prc`(환산가격) 컬럼도 있으나 과제는 `exmn_dd_prc`를 쓴다.

## ③ 문 2 — 변환·전처리 (8점)

```powershell
python q2_preprocess.py
```

| 문항 | 코드 구획 | 캡처할 출력 |
| --- | --- | --- |
| 2-1 (4점) | `# 문 2-1` ~ `# 문 2-2` 앞까지 | 1) 크기, 2) 컬럼 목록, 3) head, 4) `info()`, 5) 품종별 건수 |
| 2-2 (4점) | `# 문 2-2` 이후 | 중복 제거 / 변환 실패 건수, **월별 표본 표** (날짜→year→season 대응), 연도별·계절별 건수 |

확인 포인트:

- `season`은 **월 기준**이다 (봄 3~5, 여름 6~8, 가을 9~11, 겨울 12~2). 품종 이름과 다르다. 예를 들어 `02`(여름배추)의 10월 행은 `가을`로 나와야 정상이다. 월별 표본 표에서 이 대응이 보이면 2-2의 근거가 된다.
- 2-1의 **컬럼 목록**을 보고 단위 컬럼명(`unit` 등)을 기록해 둔다. 문 3과 문 4에서 가격 단위를 쓸 때 필요하다.
- 날짜·가격 **변환 실패 건수가 0이 아니면** 원인을 한 줄 설명한다 (예: 가격 공란 n건 제외).

## ④ 문 3 — 시각화 (8점)

```powershell
python q3_visualize.py
```

- `STUDENT_ID_LAST4 = "3257"` — 메모된 학번 153257 기준이다. **본인 학번 뒤 4자리가 맞는지 확인하고 고친다.**
- 저장 파일: `code/figures/yearly_price_3257.png`, `seasonal_price_3257.png`.
- **3-1**: 선 그래프 + 점마다 평균값. 제목은 `연도별 배추 평균 가격 변화 - 3257`.
- **3-2**: 봄·여름·가을·겨울 순서의 막대 + 막대마다 `n,nnn원` 수치 (`bar_label`).
- 축 레이블은 `원/kg`이 아니라 **"원 / 10kg 그물망 3포기"**이다. 실제 수집 데이터에서 `unit = kg(그물망 3포기)`, `unit_sz = 10`이 2015~2024년 전체에 걸쳐 같다는 것을 확인했다. 과제가 `exmn_dd_prc`는 kg당 가격이 아니라고 명시했기 때문이다.
- 그래프는 화면 캡처보다 **저장된 PNG를 직접 삽입**하는 편이 선명하다. 삽입 전에 PNG를 열어 한글 깨짐, 숫자 겹침, 학번 표기를 확인한다.

## ⑤ 문 4 — 해석 500자 (4점)

### 5-1. 근거 수치 뽑기

```powershell
python q4_check.py
```

출력에서 다음을 메모한다.

| 출력 | 메모할 것 |
| --- | --- |
| 연도별 평균·증감률 | 가장 높은/낮은 해, 전년 대비 급등·급락한 해와 증감률(%) |
| 연도 × 계절 평균 | 특정 해의 특정 계절만 튀었는지 (예: ○○년 여름·가을) |
| 연도 × 계절 건수 | 건수가 유난히 적은 칸 (평균을 믿기 어려운 칸) |
| 품종별 평균 | 고랭지(02)가 비싸서 여름·가을 평균을 끌어올리는지 |
| 연도별 최고가 일자 | 급등 시점 (추석 전, 폭염 직후 등과 연결 가능한지) |
| 거래 단위 | 연도마다 포장 단위가 바뀌었는지 (바뀌었다면 비교의 한계로 언급) |

### 5-2. 500자 구성 (4단)

1. **관찰 (약 150자)** — 본인 그래프의 수치로 쓴다. 예: "○○년 평균이 ○원으로 가장 높았고 전년보다 ○% 올랐다. 계절별로는 ○○이 가장 높았다."
2. **패턴 (약 100자)** — 연도×계절 표로 급등이 어느 계절에 몰렸는지 쓴다.
3. **원인 추론 (약 200자)** — 참고노트 6장의 공식 자료로 뒷받침한다.
   - 여름·초가을 고가: 고랭지 여름배추는 기상 영향이 크고 8~9월 가격이 높은 편이다 (농식품부).
   - 특정 연도 급등: 폭염·고온에 따른 단수 감소, 재배면적 감소 (농식품부 2024 자료), 추석 전후 출하 집중·공백 (KREI 농업관측).
   - **본인 데이터에서 실제로 보이는 연도·계절에만** 원인을 연결한다. 그래프에 없는 급등을 쓰지 않는다.
4. **한계 (약 50자)** — 가격이 포장 단위 기준이다. 품종별 관측일 수가 다르다. 가격표만으로 인과를 확정할 수 없다. 따라서 "~로 추정된다"로 맺는다.

> 이 문항은 **반드시 본인 문장으로** 쓴다. 과제 지시사항에 따라 타 학생과 표현이 일치하면 양쪽 모두 감점된다. 출처(기관명·자료명)는 문장 안에 짧게 밝힌다.

권장 구성 (문제 원문은 옮기지 않고 **문항 번호 소제목 + 답안**만 쓴다):


- **코드는 반드시 텍스트로 붙여 넣는다.** 코드를 캡처 이미지로 넣으면 지시사항 위반이다. 고정폭 글꼴(Consolas, D2Coding)을 9~10pt로 쓰고 표 한 칸 안에 넣으면 깔끔하다.

- 코드의 주석과 변수명은 **본인 말투로 조금씩 바꾼다**. 공개된 같은 템플릿을 쓰는 학생과 표현이 겹치는 것을 피하기 위해서다. 바꾼 뒤에는 다시 실행해서 캡처한다.
