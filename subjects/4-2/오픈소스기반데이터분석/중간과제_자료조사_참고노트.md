## 2. 공식 데이터와 인증

- [공공데이터포털의 해당 API 페이지](https://www.data.go.kr/data/15156057/openapi.do)는 제공기관을 한국농수산식품유통공사로 표시한다. 조회 기간의 **일평균 중도매인 판매가격·소매가격** 자료이며 조사일자, 품목·품종·등급·지역·시장 코드, 단위, 조사일가격, 조사일 kg 환산가격 등을 제공한다고 설명한다.
- 같은 페이지의 **참고문서**에 `일별 도,소매 가격정보 API명세 및 관련 코드 정보.zip`이 있다. 과제에 없는 응답 필드, 코드 전체 목록, 요청·응답 형식은 이 첨부파일을 우선 확인한다. 웹 페이지에는 REST, JSON/XML, 무료, 개발·운영 단계 자동승인, 개발계정 신청 가능 트래픽 10,000이 표시되어 있다. 서비스 조건은 바뀔 수 있으므로 실제 신청 시 페이지를 다시 확인한다.
- 계정으로 로그인한 뒤 API 페이지의 **활용신청**을 진행하고 본인 계정의 승인 상태와 키를 확인한다. 화면 구성은 계정 종류에 따라 다를 수 있다. 캡처에는 서비스명과 승인·발급 정보를 보이게 하되 **키의 상당 부분, 개인 정보, 다른 계정 정보는 가린다**. 키 원문을 과제 코드·저장소·캡처에 공개하지 않는다.
- 인증 관련 오류는 포털 페이지의 안내를 따른다. 예를 들어 키 누락·이용권한 거부는 코드 `20`, 등록되지 않은 키는 `30`, 만료된 키는 `31`, 일일 호출량 초과는 `22`, 초당 호출량 초과는 `23`으로 안내되어 있다. 오류 응답을 받은 경우 먼저 승인 상태·키·요청 주소를 확인한다. [출처: 공공데이터포털 API 상세](https://www.data.go.kr/data/15156057/openapi.do)

## 3. 수집 조건과 호출 검증

과제 원문이 지정한 엔드포인트는 `https://apis.data.go.kr/B552845/perDay/price`이다. 다음 **문자열 코드**를 그대로 보존해야 한다. 특히 `0110211`, `01`, `02`처럼 앞자리 `0`이 있는 값은 숫자로 바꾸지 않는다.

| 조건 | 값 | 해석 |
| --- | --- | --- |
| `cond[se_cd::EQ]` | `02` | 중도매(도매) |
| `cond[ctgry_cd::EQ]` | `200` | 채소류 |
| `cond[item_cd::EQ]` | `211` | 배추 |
| `cond[grd_cd::EQ]` | `04` | 상품 |
| `cond[sgg_cd::EQ]` | `1101` | 서울 |
| `cond[mrkt_cd::EQ]` | `0110211` | 가락도매 |
| `cond[vrty_cd::EQ]` | `01`, `02`, `03`, `06` | 봄·여름(고랭지)·가을·월동배추 |

날짜는 각 연도에 대해 `cond[exmn_ymd::GTE]=YYYY0101`, `cond[exmn_ymd::LTE]=YYYY1231`을 사용한다. 품종과 연도를 교차하면 **10년 × 4품종 = 최소 40개 조건 조합**이다. 품종별 대략적인 출하 시기는 봄배추 5~7월, 여름배추 7~11월, 가을배추 10~12월, 월동배추 1~5월 및 12월 일부다. 이 시기는 원문의 안내이므로 해마다 똑같은 관측일이 채워진다고 가정하지 않는다.

### 호출 순서와 확인점

1. 한 조건부터 시험한다. 원문이 제시한 `2015-01-01~2015-12-31`/품종 `01`/나머지 위 코드 조건의 기대값은 `response.body.totalCount == 66`이다. **이 값은 과제 원문의 기준이며 이 조사에서 실인증 호출로 재검증하지 않았다.**
2. 요청 변수에 `serviceKey`, `pageNo`, `numOfRows`, `returnType=JSON`과 모든 `cond[...]`를 넣는다. URL을 수작업으로 이어 붙이면 괄호·콜론 인코딩 오류가 생길 수 있다. Python Requests의 `params`는 쿼리 매개변수를 인코딩하며, `timeout`과 `raise_for_status()`는 통신 문제를 확인하는 데 도움이 된다. [출처: Requests Quickstart](https://requests.readthedocs.io/en/latest/user/quickstart/)
3. **HTTP 성공과 데이터 성공을 따로 검사**한다. `response.header`의 결과 코드·메시지, `response.body.totalCount`, 실제 목록 길이를 확인한다. JSON 파싱 성공만으로 서비스 응답의 성공이 보장되지 않는다. 실제 JSON 목록 경로와 빈 목록 형태는 인증 후 응답 및 첨부 명세에서 확인한다. [출처: Requests Quickstart](https://requests.readthedocs.io/en/latest/user/quickstart/)
4. `numOfRows=200`은 페이지당 요청 건수다. 각 조건의 `totalCount`가 200보다 크면 `pageNo`를 증가시키며 남은 페이지를 수집한다. 마지막에는 조건별 수집 행 수와 `totalCount`가 맞는지 비교한다.
5. 0건이면 바로 오류라고 판단하지 않는다. 해당 연도·품종에 자료가 없을 수도 있지만, 먼저 시장·지역·등급·품종 코드와 날짜 형식을 확인한다. `66`건 기준 호출에서 0건이라면 조건·인증·응답 구조를 다시 점검한다.
6. 반복 호출 결과에는 연도·품종·페이지별 건수를 기록한다. 재실행 시 중복 합산을 피하도록 조사일자, 시장, 품목, 품종, 등급 등 식별 열을 기준으로 중복 여부를 살핀다. 이 식별 열 조합이 실제로 유일한지는 수집 데이터로 확인한다.

인증키를 환경변수 등으로 입력하면 코드 텍스트에서 키를 분리할 수 있다. `response.url`, 예외 메시지, 저장한 원본 요청 로그에도 키가 노출될 수 있으므로 공유 전 확인한다.

## 4. 데이터 변환과 품질 점검

- 실제 응답 목록을 확인한 다음 `DataFrame`으로 만든다. `shape`, `columns`, `head()`, `info()` 등으로 행·열 수, 자료형, 결측치를 살핀다. `DataFrame.info()`는 열별 비결측 수와 자료형을 요약한다. [출처: pandas `DataFrame.info`](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.info.html)
- `exmn_ymd`는 `YYYYMMDD` 형식으로 해석해 날짜형으로 바꾼 뒤 `.dt.year`, `.dt.month`로 연도와 월을 추출한다. `pandas.to_datetime(..., format="%Y%m%d", errors="coerce")`는 파싱 불가능한 값을 `NaT`로 만들 수 있다. 변환 뒤 `NaT` 개수를 확인한다. [출처: pandas `to_datetime`](https://pandas.pydata.org/docs/reference/api/pandas.to_datetime.html)
- 계절은 **월 기준**으로 봄 3~5월, 여름 6~8월, 가을 9~11월, 겨울 12~2월이다. `season`은 **배추 품종명과 별개**다. 예를 들어 `여름배추` 품종의 10월 관측은 계절 열에서는 `가을`이다.
- 가격 `exmn_dd_prc`를 숫자로 바꾸기 전에 실제 형식을 확인한다. 문자형 숫자에 쉼표나 결측 표시가 섞였다면 정리한 뒤 `pandas.to_numeric(..., errors="coerce")`로 변환하고, 변환 실패 건수를 기록한다. 오류값을 무조건 0원으로 만들지 않는다. [출처: pandas `to_numeric`](https://pandas.pydata.org/docs/reference/api/pandas.to_numeric.html)
- 원문은 `exmn_dd_prc`가 **원/kg이 아니라 해당 거래의 포장 단위 가격**이라고 명시한다. API 설명에는 `단위`, `단위크기`, `조사일kg환산가격`도 제공 항목으로 나온다. 과제에서 지정한 가격 열은 `exmn_dd_prc`이므로 그래프의 축을 임의로 `원/kg`으로 쓰지 말고 실제 단위를 확인해 표기한다. 연도·품종별 포장 규격이 다르면 단순 평균 비교에도 한계가 있다. [출처: 공공데이터포털 API 상세](https://www.data.go.kr/data/15156057/openapi.do)
- 결측 날짜, 비영업일, 품종별 출하 기간 차이, 해마다 다른 관측 건수를 살핀다. 한 행을 한 관측값으로 놓은 단순 평균은 **관측일 수가 많은 품종·시기**에 더 큰 비중을 준다. 요청한 값의 평균 방식과 이 한계를 설명할 준비를 한다.

## 5. 집계와 그래프를 검토할 때

| 산출물 | 집계 기준 | 표시·검증 사항 |
| --- | --- | --- |
| 연도별 선 그래프 | `year`별 `exmn_dd_prc` 평균 | 2015~2024년 표시, 제목에 본인 학번 뒤 4자리, 가격 단위·누락 연도 확인 |
| 계절별 막대 그래프 | `season`별 `exmn_dd_prc` 평균 | 봄·여름·가을·겨울 순서, 각 막대 수치, 단위·관측 건수 확인 |

[출처: pandas `groupby`](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.groupby.html), [출처: pandas `GroupBy.mean`](https://pandas.pydata.org/docs/reference/api/pandas.api.typing.DataFrameGroupBy.mean.html)

[출처: Matplotlib `bar_label`](https://matplotlib.org/stable/api/_as_gen/matplotlib.pyplot.bar_label.html), [출처: Matplotlib `savefig`](https://matplotlib.org/stable/api/_as_gen/matplotlib.pyplot.savefig.html)

연도별 평균과 계절별 평균만으로 개별 가격 급등일의 원인을 증명할 수 없다. 가능하면 **연도×계절별 평균·건수**와 월별 흐름도 내부 검산에 사용하고, 제출 그래프에는 과제가 요구한 두 그래프를 명확히 제시한다. `품종별 평균`, `연도별 단위/단위크기 변화`도 해석을 점검할 때 유용하다.

500자 해석은 본인 결과에서 **어느 연도·계절이 어느 정도 높거나 낮은지 → 예외나 데이터 한계가 있는지 → 공식 자료가 제시한 가능한 요인 → 인과관계의 불확실성** 순으로 구성하면 검증하기 쉽다. `~때문이다`라고 단정하려면 추가 근거가 필요하므로, 가격표만으로 확인할 수 없는 원인은 추론으로 표시한다.

## 자료 확인 상태

- 과제 원문과 위 공식 페이지·문서의 공개 설명을 확인했다.

- 공식 API 페이지의 등록일·수정일과 이용 조건은 조사일 당시 화면에 표시된 내용이다. 제출 전 최신 화면과 첨부 명세를 다시 확인한다.
