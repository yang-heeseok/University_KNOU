## 작업 1 — 문 4 해석 재작성

### 현재 상태
docx 마지막 쪽 `문 4. 데이터 분석 및 해석` 아래에 한 문단이 있다. 이전 세션이 쓴 예시 초안이고, 런마다 노란 형광펜(`<w:highlight w:val="yellow"/>`)이 붙어 있다. 그 원문은 다음과 같다.

> 2015~2024년 가락시장 배추(상품, 10kg 그물망) 평균 도매가격은 5,930원에서 15,846원으로 약 2.7배 올랐다. 2016년(+80.6%), 2020년(+49.9%), 2022년(+53.8%), 2024년(+35.3%)에 급등하고 이듬해 내리는 등락을 반복하면서 전체적으로 우상향했다. 계절별로는 가을(12,928원)과 여름(11,121원)이 겨울(7,572원)보다 1.5~1.7배 높았다. 연도별 최고가는 10년 중 9년이 8~10월 고랭지 여름배추에서 나왔고, 이 품종 평균(15,441원)은 다른 품종의 약 2배였다. 고랭지배추는 강원 산간에 생산이 몰려 있어 폭염·장마·태풍에 작황이 크게 흔들린다. 2016년 8월 폭염, 2020년 최장 장마와 잇단 태풍, 2022년 태풍 힌남노, 2024년 장기 폭염이 가격 급등 연도와 겹치는 것도 이 때문으로 보인다. 다만 이 수치는 포장 단위 가격의 단순 평균이고 기상 자료와 직접 대조하지 않았으므로, 기후 요인은 가능성이 높은 추정으로 보아야 한다.

### 해야 할 일
1. 이 문단을 **새 문장으로 다시 쓴다.** 어순, 문장 구성, 접속 표현, 강조 순서를 바꾼다. 위 초안이나 흔한 AI 문체("~로 보인다", "전체적으로 우상향" 등)의 표현을 그대로 반복하지 않는다. 숫자, 연도, 고유명사가 겹치는 것은 괜찮다.
2. 분량: **공백 포함 450~550자.**
3. 구성: 관찰(수치) → 패턴 → 원인 추론 → 한계. 한계는 단순 평균이라는 점, 포장 단위 가격이라는 점, 기상 자료와 직접 대조하지 않았다는 점 등을 말하고, 원인은 추정으로 표현한다. 순서나 비중은 바꿔도 된다. 예를 들어 계절 패턴부터 시작해도 좋다.
4. 사실은 아래 표에 있는 것만 쓴다. 표에 없는 수치나 원인을 새로 만들지 않는다.
5. docx에서 해당 문단 텍스트를 바꾸고 **형광펜을 제거**한다. 글꼴(맑은 고딕 10pt), 줄 간격, 양쪽 정렬은 유지한다.
6. 문제 원문은 답안에 옮겨 적지 않는다. 소제목 `문 4. 데이터 분석 및 해석`은 그대로 둔다.

원인 근거 (보도·공식 자료, 원인은 추정으로만 쓴다):
- 2016: 8월 폭염으로 고랭지배추 작황 부진, 10kg 도매가가 전년의 약 3배 (경북매일 2016-10-25, 매일신문 2016-09-08)

### 검증
- 글자 수: 공백 포함 450~550자 (Python `len()`).
- 위 초안과 겹치는 표현: 숫자와 고유명사를 뺀 **연속 10자 이상 공통 부분 문자열이 없을 것.** `difflib.SequenceMatcher(...).get_matching_blocks()` 등으로 확인한다.
- 본문의 모든 수치를 위 표와 하나씩 대조한다.

## 작업 2 — 코드 주석 수정

### 해야 할 일
1. `code/q1_collect.py`, `code/q2_preprocess.py`, `code/q3_visualize.py`에서 **`#` 주석만** 본인 말투로 바꾼다. 파일마다 3~6줄 정도면 된다. 표현을 바꾸거나, 짧게 줄이거나, 설명을 덧붙여도 된다.
2. **바꾸면 안 되는 것:**
   - 코드 동작. 변수명, 함수명, 로직, 들여쓰기.
   - **문자열 리터럴 전부.** 특히 `print(...)` 안의 텍스트는 실행 결과 캡처에 그대로 찍혀 있으므로, 바꾸면 코드와 캡처가 어긋난다.
   - `q1_collect.py`의 docstring `"""body.items ..."""`. 문자열이라 AST가 달라지므로 그대로 둔다.
   - 문항 구획 주석 `# ---------------- 문 2-2.`, `# ---------------- 문 3-2.`의 앞부분. docx에서 이 줄을 경계로 코드를 2-1/2-2, 3-1/3-2로 나눴기 때문이다. 구획 주석의 `문 X-Y.` 뒤 설명 문구는 바꿔도 된다.
   - `STUDENT_ID_LAST4 = "3257"` 값.
3. 인증키 원문을 어디에도 쓰지 않는다. 코드는 환경변수 `DATA_GO_KR_KEY`로 키를 읽는다.

### 검증
- 수정 전후 `ast.dump(ast.parse(src))` 결과가 **완전히 같아야 한다.** 주석만 바뀌었다는 증거다. 수정 전 원본은 작업 시작 시 스크래치패드에 복사해 둔다.
- `python -m py_compile`이 통과해야 한다.
- 다시 실행할 필요는 없다. AST가 같으면 출력도 같다.

## 작업 3 — docx 반영 (작업 1·2 공통)

docx 스킬(`anthropic-skills:docx`)을 먼저 로드하고, **기존 docx를 편집**하는 방식으로 진행한다. 새로 만들지 않는다.

1. 작업 전 원본 docx를 스크래치패드에 백업한다. Word에서 파일이 열려 있으면(`~$` 잠금 파일이 있으면) 사용자에게 닫아 달라고 요청한다.
2. 압축을 풀고 `word/document.xml`을 편집한다. 압축은 Python `zipfile`로 하고 `[Content_Types].xml`을 첫 항목으로 넣는다. 이 환경에는 `zip`, `pandoc`, LibreOffice가 없다.
3. **코드 블록 구조:** 코드는 회색(F3F3F3) 1칸 표 안에 있다. 코드 한 줄이 문단 하나이고, 문단 안에 `<w:r>` 하나와 `<w:t xml:space="preserve">줄 내용</w:t>`이 들어 있다(Consolas 8pt, `&lt;` `&amp;` 등은 XML 이스케이프). 주석을 바꾼 줄만 찾아서 `<w:t>` 내용을 새 줄로 바꾼다. 새 줄도 이스케이프한다. 바꾼 뒤 docx 안의 코드 줄을 순서대로 모으면 수정된 .py 파일 내용과 **한 줄도 다르지 않아야 한다.**
   - q1 → `[코드] q1_collect.py` 아래 표 1개
   - q2 → 2-1 표(파일 처음부터 `# ---------------- 문 2-2` 직전까지)와 2-2 표(그 줄부터 끝까지)
   - q3 → 3-1 표(처음부터 `# ---------------- 문 3-2` 직전까지)와 3-2 표(그 줄부터 끝까지)
4. **문 4:** 형광펜이 있는 런들을 새 문단 텍스트로 바꾸고 `<w:highlight .../>`를 제거한다. 문서 전체에 `w:highlight`가 0개여야 한다.
5. 검증 순서:
   - docx 스킬의 `scripts/office/validate.py out.docx --original <백업>` 실행. `-I` 없이 실행해야 helpers를 불러온다. 필요하면 `pip install defusedxml lxml`.
   - Word COM(PowerShell: `Word.Application` → `SaveAs2(pdf, 17)`)으로 PDF를 만든다.
   - PyMuPDF(`fitz`)로 코드 쪽 1~2장과 문 4 쪽을 이미지로 만들어 직접 확인한다.
   - 인증키가 없는지 확인한다: 64자리 hex 패턴 `[0-9a-f]{64}`이 document.xml에 0건이어야 한다.
6. 검증을 통과하면 원래 경로에 덮어쓴다.
